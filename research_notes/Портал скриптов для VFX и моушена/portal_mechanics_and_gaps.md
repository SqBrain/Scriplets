# Portal mechanics, risks and unmet needs for a VFX / motion-design script hub

Research date: 2026-10-20. Scope: distribution/installation, trust and security, licensing (including AI-written code), monetization, community/discovery, unmet needs.

**How these notes were gathered (please read):** WebFetch could not open almost any page in this session. Hosts such as av-comparatives.org, bleepingcomputer.com, developer.adobe.com, docs.blender.org and superhivemarket.com failed DNS lookup or were refused by the egress proxy, and aescripts.com and extensions.blender.org were also proxy-refused. The web-search budget for the session ran out after about 60 queries. So almost every finding below comes from search-engine summaries and snippets of the cited pages, not from reading the pages in full. Exact figures (fees, counts, dates) should be checked on the primary page before anyone relies on them. Where a summary flagged a source as secondary, anecdotal or contradicted, the note says so.

**User context (checked in the local repo /home/user/Scriplets):** about 50 After Effects `.jsx` scripts sit in the repo root. Two of them also ship as compiled `.jsxbin` (`Rule tangets`, `addControllableMatte`), one ships as a `.rar`, and one preset is an `.ffx` (`true/PS_Rect_Controller.ffx`). There is a shared helper library, `lib/index.jsx`, which pulls in 15 modules through `//@include "./..."`. Scripts load it with relative includes such as `//@include "./lib/index.jsx"`. `MattePresetBinnaryCode.jsx` embeds a binary preset as a string. At least `addControllableMatte.jsx`, `Expressions Changer.jsx` and `lib/fileDataFunctions.jsx` use `File(` / `callSystem` / `Socket`, which means they need AE's file/network scripting permission. `package.json` declares the MIT license.

## 1. Distribution & installation: how tools get installed per host, and what one-click installers or package managers exist that a portal could integrate with or copy

### Takeaway
Each host has its own install mechanism. In AE, plain scripts are file copies, and CEP/ZXP extensions need a third-party installer. Blender's extension system (4.2+) is the most portal-friendly: any third-party server can publish a JSON index that Blender reads as a "remote repository", with in-app install and updates. Superhive (formerly Blender Market) already uses it, including for paid add-ons. Fusion/Resolve has a working community package manager (Reactor). The aescripts manager app is the closest thing AE has to a package manager, but it is closed and tied to aescripts' store. A new portal could (a) publish a Blender-compatible repository index, (b) ship a small AE "manager" ScriptUI panel or CEP/UXP panel that installs scripts and resolves shared libraries, and (c) produce manifests for Houdini packages and Nuke `init.py`/`menu.py`.

### Cited Findings
**After Effects (ExtendScript / ScriptUI)**
- Adobe's help says scripts with a dockable UI belong in the `ScriptUI Panels` folder and then appear at the bottom of the Window menu. Plain scripts go in `Scripts` and run from File > Scripts. — [Adobe Help: Scripts in After Effects](https://helpx.adobe.com/after-effects/using/scripts.html)
- By default, AE scripts **cannot write files or use the network**. The user has to enable *Settings/Preferences > Scripting & Expressions > "Allow Scripts To Write Files And Access Network"*. Vendors report a first-run error or silent failure until it is on, and a greyed-out checkbox that needs an app restart or a first launch as admin on Windows. — [Adobe Help](https://helpx.adobe.com/after-effects/using/scripts.html); [Battle Axe Rubberhose 2 help](https://help.battleaxe.co/rubberhose2); [LottieFiles AE install docs](https://docs.lottiefiles.com/en/integrations/after-effects/01_quickstart/installation)
- Typical vendor install paths: macOS `/Applications/Adobe After Effects <ver>/Scripts/ScriptUI Panels/`; Windows `C:\Program Files\Adobe\Adobe After Effects <ver>\Support Files\Scripts\ScriptUI Panels\`. These folders are per version and need admin rights on Windows. — [Battle Axe help](https://help.battleaxe.co/rubberhose2)
- Where to put a script matters. In an AE 25.4 thread, a Camera Rig panel opened but did nothing, and a community responder advised moving it from `ScriptUI Panels` to `Scripts`. — [Adobe Community: camera crew script panel not working in AE 2025](https://community.adobe.com/questions-529/camera-crew-script-panel-not-working-in-after-effects-2025-60622)

**CEP / ZXP extensions (AE, Premiere and other Adobe apps)**
- Adobe's own Extension Manager CC was retired after CC 2015. Adobe forum experts point users to **Anastasiy's Extension Manager** (install.anastasiy.com) instead. Adobe's supported command-line tool is **UPIA** (Unified Plugin Installer Agent), which replaced ExManCmd and ships with Creative Cloud 5.5+. The fallback is to rename `.zxp` to `.zip` and extract it into the CEP `extensions` folder. Users report that Anastasiy's tool breaks after CC updates and that macOS Gatekeeper blocks unsigned packages. — [Adobe Community (Illustrator ZXP thread)](https://community.adobe.com/questions-652/how-to-packaging-and-install-zxp-for-illustrator-cc-2015-3-and-cc-2017-813852); [Approval.studio manual-install guide (PDF)](https://Approval.studio/wp-content/uploads/2023/09/GUIDE-FOR-MANUAL-INSTALLATION-2-5-1.pdf); [Adobe Extension Manager CC deprecation notice (PDF mirror)](https://www.psdcovers.com/wp-content/uploads/2017/12/Adobe-Extension-Manager-CC-2014-Deprecation-Notice.pdf)
- aescripts also lists a "ZXP Installer" product page, so aescripts promotes its own ZXP install path. — [aescripts ZXP installer page (URL seen in search results)](https://aescripts.com/directory/currency/switch/currency/EUR/uenc/aHR0cHM6Ly9hZXNjcmlwdHMuY29tL3p4cC1pbnN0YWxsZXIv/)

**UXP (Adobe's successor to CEP)**
- Adobe's AE UXP developer page describes plugins, scripts and panels built on shared UXP APIs plus AE-specific APIs. It says docs and samples will keep expanding "throughout the beta", so **AE UXP was still in beta** at the time of the search (2026). — [Adobe Developer: After Effects UXP](https://developer.adobe.com/after-effects/uxp/)
- For comparison, Adobe announced in December 2025 that UXP "officially graduated from beta" in **Premiere 25.6**. — [Adobe Developer Blog, Dec 2025: UXP Arrives in Premiere](https://blog.developer.adobe.com/en/publish/2025/12/uxp-arrives-in-premiere-a-new-era-for-plugin-development)
- A March 2025 forum answer said UXP was then only in Premiere beta builds, with no date for AE. 2026 forum threads ask "When will UXP come to After Effects?", and one from February 2026 is titled "After Effects 2025 – CEP Removal and UXP Panel Support Issue". Their content was not visible to me. — [Creative Cloud Developer forum: UXP vs CEP for Premiere & AE](https://forums.creativeclouddeveloper.com/t/uxp-vs-cep-for-premiere-pro-after-effects-which-should-i-use/10364)
- An April 2026 AE beta rebuilt the Effect Controls panel as "the first stage of a larger project to modernize the UX framework of After Effects". This is native UI work, not UXP. — [Adobe Community announcement (Apr 2026)](https://community.adobe.com/announcements-532/new-in-beta-modernized-effect-controls-panel-1556351)
- Adobe's **Creative Cloud Marketplace** (web Exchange plus the Plugins tab in the CC desktop app) lists UXP plugins after a quality review, through the Developer Distribution portal (which replaced the Developer Console in 2023). — [Adobe Developer Distribution FAQ](https://developer.adobe.com/developer-distribution/creative-cloud/docs/guides/faq); [Adobe Developer blog (Mar 2023)](https://blog.developer.adobe.com/en/publish/2023/03/introducing-a-new-developer-distribution-portal-for-listing-uxp-plugins-in-the-creative-cloud-marketplace); [Premiere UXP: Adobe Marketplace distribution](https://developer.adobe.com/premiere-pro/uxp/plugins/distribution/adobe-marketplace)

**aescripts + aeplugins manager app (closest AE precedent for a package manager)**
- It is a standalone macOS/Windows desktop app. You sign in with an aescripts account, and from "All Products" you install, **update**, **license** and **install trials** of products. You can add custom search folders when a host app is not found in its default location. — [aescripts Manager App FAQ](https://aescripts.com/knowledgebase/index/view/faq/aescripts-aeplugins-manager-app-faq/); [Dataclay Templater: installing via the aescripts manager](https://support.dataclay.com/templater/content/introduction/welcome/installation/installation_via_aescripts_manager.htm)
- Buyers first get a **temporary 30-day serial**, which they must swap for a permanent one. "License not recognized" errors usually come from that temporary serial. — [Toolfarm: download, install & register aescripts products](https://www.toolfarm.com/?p=66377); [aescripts: how to register plugins](https://aescripts.com/knowledgebase/index/view/faq/how-to-register-plugins/)

**Blender (4.2+ Extensions)**
- Blender's manual documents third-party extension repositories at three levels: (1) a **static JSON** index (`index.json`) built with `blender --command extension server-generate` from a folder of packages, (2) a dynamic server that serves the JSON per Blender version and platform, or (3) forking the whole Extensions Website. Users add the URL under Preferences > Extensions > Repositories (`file://` works for testing). Download links must end in `.zip`. `server-generate` can also emit an HTML listing. Custom tags need a patch to `tags.py` to be translated. — [Blender Manual: Creating an Extensions Repository](https://docs.blender.org/manual/en/4.2/advanced/extensions/creating_repository/index.html); [Blender Manual 4.3: Static Extensions Repository](https://docs.blender.org/manual/en/4.3/advanced/extensions/creating_repository/static_repository.html)
- **Superhive (formerly Blender Market)** registers itself as a remote extension repository using the buyer's **API token**. Purchases then show up in Blender's Get Extensions, and **updates arrive inside Blender** whenever the creator publishes a new version. Only products marked "Blender Extension Compatible" work this way; older add-ons use the legacy zip install. — [Superhive: Announcing Remote Extension Support](https://superhivemarket.com/posts/blender-extension-support-launched-on-superhive)
- Per-extension download counts on extensions.blender.org, for scale: Icon Viewer about 26.3k and Scene Information about 20.8k (both published 14 May 2024), ZModeler3 theme 3,293. I found no site-wide total. — [extensions.blender.org: Icon Viewer](https://extensions.blender.org/add-ons/icon-viewer/); [Scene Information](https://extensions.blender.org/add-ons/scene-information/)

**Fusion / DaVinci Resolve**
- **Reactor** (We Suck Less community) is a free, open-source package manager for Fusion and Resolve. Packages are "Atoms" synced from an online Git repository (GitLab: WeSuckLess/Reactor), with one-click install and update of scripts, plugins, macros and templates. Reactor 2.0 (May 2018) added Resolve support. It runs on Windows, macOS and Linux. — [CG Channel, 23 May 2018](https://www.cgchannel.com/2018/05/we-suck-less-ships-reactor-2-0/); [CGPress: Reactor 2.0](https://cgpress.org/archives/reactor-2-0-for-resolve-and-fusion-released.html); [Toolfarm](https://www.toolfarm.com/news/freebie_fusion_download_reactor_2-0_for_free/)

**Houdini**
- SideFX's plugins reference shows package JSON files in the user-preferences `packages` folder, each with an `hpath` entry that prepends to `HOUDINI_PATH`. `HOUDINI_PACKAGE_DIR` points at extra package folders; per forum advice it must be a real OS environment variable, not set via `houdini.env` (unverified). `HOUDINI_PACKAGE_VERBOSE=1` turns on debug output. — [SideFX docs: plugins/packages](https://download.sidefx.com/docs/houdini/ref/plugins.html); [SideFX forum: shared packages folder](https://www.sidefx.com/forum/topic/93602/)

**Nuke**
- Nuke scans `~/.nuke` automatically. `init.py` runs on every launch (GUI and command line) and should register folders with `nuke.pluginAddPath()`. UI and menu entries belong in `menu.py`, because building UI in `init.py` can stop Nuke from starting. Within each plugin directory, `init.py` runs before `menu.py`. `NUKE_PATH` is the environment-variable alternative for studio-wide paths. — [Foundry Python Dev Guide: Installing Plug-ins](https://learn.foundry.com/nuke/developers/90/pythondevguide/installing_plugins.html); [Foundry: Start-up Scripts](https://learn.foundry.com/nuke/developers/80/pythondevguide/startup.html); [Foundry Nuke 12.1: Defining the plug-in path](https://learn.foundry.com/nuke/12.1/content/comp_environment/configuring_nuke/defining_nuke_plugin_path.html); [Nukepedia: Getting started with Nuke plugins](https://www.nukepedia.com/knowledge/general-tutorials/getting-started-with-nuke-plugins/)
- Nukepedia promotes **nuBridge**, which offers "over 1,300 tools right inside of Nuke": an in-app browser and installer for a community hub. — [Nukepedia nuBridge](https://www.nukepedia.com/nubridge/)

**ComfyUI (relevant adjacent precedent: node packs installed by a manager)**
- The Comfy Registry and ComfyUI-Manager install custom node packs. Nodes that pass the registry's malware scan get a **verification flag** in the Manager UI. — [Comfy Registry docs](https://docs.comfy.org/registry/overview.md)

### Inferences
- The user's repo layout (scripts in the root that `//@include "./lib/index.jsx"`, and a lib that includes 15 modules) **breaks if a user copies a single `.jsx` into `ScriptUI Panels`**, because the relative include no longer resolves. A portal needs one of three approaches: (a) bundle at publish time, inlining includes into a single file (a jsxbin export from the VSCode ExtendScript debugger also inlines them, which may be why the user ships `.jsxbin` for the larger scripts); (b) treat the lib as a declared dependency installed to a shared path; or (c) a manager panel that resolves dependencies. This is a real gap: none of the AE distribution options above has a dependency model for shared ExtendScript libraries.
- The pieces a portal can integrate with directly, at low cost: a **Blender static `index.json`** (no client work needed); **Reactor-style Git-backed atoms** for Fusion; **Houdini package JSON** files and **Nuke `init.py`/`menu.py` snippets** generated per tool. AE has no open equivalent of the aescripts manager, so a free, open "manager" ScriptUI panel or CEP/UXP panel that installs, updates and checks the AE version would be the unique piece. It should also tell the user when a script needs the "Allow Scripts to Write Files" permission. Several of the user's scripts need it.
- Because AE UXP is still beta and CEP's future is uncertain, a ScriptUI-based manager is the lowest-risk option in 2026. UXP packaging (`.ccx`) can be added later.

### Gaps
- Could not open Blender's manual to quote the exact JSON schema field names (e.g., `archive_url`, `archive_hash`, `blender_version_min`, `permissions`, `platforms`). Background knowledge, not verified this session: Blender 4.2 (2024) added `blender_manifest.toml` with a declared `permissions` list (files, network, clipboard, camera, microphone). The permissions are informational, not enforced by a sandbox.
- No primary source found on how a UXP `.ccx` is sideloaded in AE beta, or on CEP deprecation dates for AE.
- No source found on Maya modules (`.mod`), the Autodesk App Store, Cinema 4D/Maxon plugin installation, or the current status of SideFX's Orbolt HDA store. The search budget ran out.
- No data on how many AE users actually use the aescripts manager vs. manual install.

## 2. Trust & security: malware precedents in creative-software scripts/assets, and how platforms mitigate

### Takeaway
Malware in creative-tool content is no longer hypothetical. Between 2024 and 2026 there were (1) a Russian-speaking group spreading the StealC V2 infostealer through `.blend` files on CGTrader that auto-run embedded Python, (2) a self-replicating Maya scene worm found in assets sold on Epic's Fab.com (39 sellers unknowingly affected), (3) a malicious ComfyUI node pack (LLMVISION) tied in reporting to the Disney Slack breach, and (4) a long-running wave of cracked AE/plugin downloads delivering infostealers. Mature platforms respond with no-obfuscation rules (Greasy Fork, Comfy Registry), automated scans plus manual review for popular items (Obsidian 2026, Comfy, VS Code), and remote kill-switches (VS Code). `.jsxbin` gives weak IP protection (public decompilers exist) and makes review much harder. A portal should therefore require readable source for review, even when it ships a binary.

### Cited Findings
**Precedents**
- **Blender `.blend` + StealC V2 (reported Nov 2025, Morphisec):** a Russian-speaking group planted `.blend` files on **CGTrader** and similar 3D marketplaces, active for at least six months. Embedded Python (e.g., `Rig_Ui.py`) runs when the victim has **"Auto Run Python Scripts"** enabled. It fetches a loader, then a PowerShell stage, then two ZIPs: StealC V2 plus a Python stealer, persisted through Startup-folder LNKs. Researchers said it was **undetected by all major AV engines on VirusTotal** at discovery. Because Blender machines usually have GPUs, the malware also slipped past VM-based sandboxes. StealC V2 targets 23 browsers, 100+ browser extensions and 15 wallet apps. — [BleepingComputer](https://www.bleepingcomputer.com/news/security/malicious-blender-model-files-deliver-stealc-infostealing-malware/); [The Hacker News, Nov 2025](https://thehackernews.com/2025/11/hackers-hijack-blender-3d-assets-to.html); [Infosecurity Magazine](https://www.infosecurity-magazine.com/news/russian-malware-blender-3d-files/); [Security Affairs](https://securityaffairs.com/?p=185052); [HivePro advisory](https://hivepro.com/threat-advisory/stealc-v2-spreads-via-malicious-blender-files/)
- **Maya worm on Fab.com (AV-Comparatives, 2025–2026):** **39 sellers unknowingly uploaded** Maya scene files infected with a self-replicating Python worm, and buyers received them. ESET detects it as **MEL/Vacphage.A** (since at least Jan 2021); Bitdefender calls it Generic.MayaWorm.Phage.A and Microsoft Virus:Python/Vaccworm!MTB. After responsible disclosure, Epic removed the listings, notified users and released a detection tool within the 90-day window. The 39-seller count is AV-Comparatives' preliminary figure; I found no independent Epic statement. — [AV-Comparatives: Malware in the Marketplace](https://av-comparatives.org/maya-malware-fab-com/); press release syndication, e.g. [Kyodo PR Wire, 15 Jun 2026](https://kyodonewsprwire.jp/release/202606150888)
- **Maya "Vaccine" scene virus (community, 2021–2022+):** it spreads through scene files and `userSetup.py`. Autodesk published **Security Tools for Maya** on its App Store, but users say it cleans files rather than Maya itself and that infections came back. Community tools such as `maya-umbrella` (PyPI) emerged, and a deobfuscated source analysis was posted by mottosso. — [Autodesk forum: Maya Vaccine Virus](https://forums.autodesk.com/t5/maya-forum/maya-vaccine-virus/td-p/11518721); [tech-artists.org: Maya virus warning](https://www.tech-artists.org/t/maya-virus-warning/12565); [maya-umbrella on PyPI](https://pypi.org/project/maya-umbrella/0.10.0); [Core Security: Autodesk Maya scriptNode exploit](https://www.coresecurity.com/core-labs/exploits/autodesk-maya-scriptnode-exploit)
- **ComfyUI_LLMVISION (June 2024):** a ComfyUI custom node attributed to the "Nullbulge" group pinned **tampered `openai`/`anthropic` wheels** in its requirements. The payload sent browser passwords, cards and history to a Discord webhook. Reports link it as *one candidate vector* in the 2024 Disney Slack leak (44M messages); a BeamNG mod and an insider are the alternatives. The link is reported, not confirmed. — [GIGAZINE, 11 Jun 2024](https://gigazine.net/gsc_news/en/20240611-comfyui-llmvision-malware); [ThreatLocker: Disney breach](https://threatlocker.com/blog/disney-security-breach); [AI Incident Database #950](https://incidentdatabase.ai/fr/cite/950)
- **ComfyUI "Upscaler-4K" (Oct 2024):** malicious packs were published to the Comfy Registry and banned after an automated scanner flagged them and the registry team reviewed them manually. One commenter claimed a banned pack was still installable through Manager (unverified). — [Comfy blog: Upscaler-4K post-mortem](https://blog.comfy.org/p/upscaler-4k-malicious-node-pack-post)
- **Cracked AE and plugins as an infostealer vector:** ESET (Mar 2023) documented a victim who downloaded a "cracked After Effects" from a YouTube description link and lost Instagram, Steam, Spotify and other credentials. Cyble documented a YouTube campaign with After Effects among 100+ lure apps. CloudSEK (via TechRadar) reported a Pakistan-linked pay-per-install network spreading infostealers disguised as cracked software, After Effects included, with more than **$4M** in tracked revenue. A user on a forum noted VirusTotal showed nothing for a cracked AE 2025. — [ESET WeLiveSecurity (ES), 9 Mar 2023](https://www.welivesecurity.com/la-es/2023/03/09/descargo-crack-after-effects-infecto-troyano-robo-contrasenas/); [Cyble](https://cyble.com/blog/massive-youtube-campaign-targeting-over-100-applications-to-deliver-info-stealer/); [TechRadar](https://www.techradar.com/pro/security/pakistani-based-malware-empire-punished-software-pirates-with-infostealers-earning-millions-of-dollars-in-just-five-years-heres-how-to-stay-safe); [yomotherboard Q&A](https://yomotherboard.com/question/is-this-after-effects-download-a-virus/)
- **VS Code Marketplace (npm-style ecosystem analogue):** in a June 2025 post, Microsoft said that "so far this year" it had **reviewed 136 extensions for malicious code and removed 110**. Removed malicious extensions are **remotely blocked/force-uninstalled** in VS Code, and Microsoft monitors for publisher impersonation. Incidents include two "ahban.*" extensions with early-stage ransomware that stayed listed for months after a Nov 2024 report, and a fake "Prettier Plus" (Nov 2025) removed within 4 hours with 6 downloads. — [Microsoft Developer Blog, 11 Jun 2025](https://developer.microsoft.com/blog/security-and-trust-in-visual-studio-marketplace/); [BleepingComputer: VSCode extensions downloading ransomware](https://www.bleepingcomputer.com/news/security/vscode-extensions-found-downloading-early-stage-ransomware/); [Checkmarx Zero](https://checkmarx.com/zero-post/checkmarx-zero-takes-down-malicious-prettier-alternative-found-in-vscode-marketplace.md)

**Mitigations used by other hubs**
- **Greasy Fork (userscripts):** "Code posted to Greasy Fork must not be obfuscated or minified. Users must be given the opportunity to inspect and understand a script before installing it." Bundler output must stay readable. There is a 2 MB cap, and minifying to fit under it is not allowed. Moderators may delete violators. — [Greasy Fork: Code rules](https://greasyfork.org/he/help/code-rules)
- **Comfy Registry standards:** obfuscation is **prohibited**; runtime `pip install` through `subprocess` is banned; `eval`/`exec` on user input is restricted. All nodes are scanned (AI plus static analysis, with the rules kept private). The Jan 2025 roadmap: gradual **author verification**, a Manager feature to **remotely disable** malicious nodes, and CI that runs nodes on example graphs. Completion status unknown. — [Comfy Registry standards](https://docs.comfy.org/registry/standards); [Comfy blog: Jan 2025 Security Update](https://blog.comfy.org/p/comfyui-2025-jan-security-update)
- **Obsidian (May 2026 overhaul):** Obsidian **automatically scans every plugin version** for vulnerabilities, code-quality issues and malware. It shows a **safety scorecard** on each plugin page and keeps manual reviews for popular, featured and flagged plugins. It plans disclosures, privacy labels and **artifact attestation**. It warns users that plugins can read files, use the network and install programs. — [Obsidian Help: Plugin security](https://obsidian.md/help/plugin-security); [Obsidian blog: The future of plugins](https://obsidian.md/blog/future-of-plugins/); [GIGAZINE, 13 May 2026](https://www.gigazine.net/gsc_news/en/20260513-obsidian-plugin-future)
- **Raycast Store:** every extension is submitted as a **pull request to the public `raycast/extensions` repo**, under the MIT license (`license: MIT` in package.json), and reviewed by community managers first-in-first-out ("first contact within a week"; 10–15 business days in summer). The PR also needs a distribution build and a `package-lock.json`. — [Raycast: Prepare an extension for the Store](https://developers.raycast.com/basics/prepare-an-extension-for-store); [Raycast: Publish an extension](https://developers.raycast.com/basics/publish-an-extension)
- **Blender's built-in mitigation:** Blender's docs warn that embedded Python is a security risk because Python does not restrict what a script can do. Morphisec advises keeping Auto Run off unless the source is trusted. — [The Hacker News (citing Blender docs and Morphisec)](https://thehackernews.com/2025/11/hackers-hijack-blender-3d-assets-to.html)
- **AE's built-in mitigation:** file and network access for scripts is **off by default** and needs an explicit preference toggle. This is a coarse global switch, not per-script. — [Adobe Help: Scripts](https://helpx.adobe.com/after-effects/using/scripts.html)

**The jsxbin debate**
- **jsxer** is a C++ decompiler that turns JSXBIN back into JavaScript, with experimental "JSXBlind" deobfuscation (`--unblind`). Its README says the earlier `jsxbin-to-jsx-converter` "vanished as a consequence of a DMCA takedown from Adobe", though forks survive. Other converters exist, including an ExtendScript Toolkit plugin that opens `.jsxbin` directly. — [jsxer (GitHub)](https://github.com/infinity236/jsxer); [jsxbin-to-jsx-converter fork](https://github.com/zhiqiang-li/jsxbin-to-jsx-converter); [ESTK jsxbintojsx plugin](https://github.com/KarlPan/extendscript-toolkit-jsxbintojsx-plugin)
- AE community experts describe two DIY licensing approaches for scripts, a phone-home check over a socket or a local key check, and stress making them hard to strip or reverse. Both rely on obscuring code, which in practice means jsxbin. — [Adobe Community: license key for my script (2021)](https://community.adobe.com/t5/after-effects-discussions/license-key-for-my-script/m-p/12463623)

### Inferences
- The threats with real precedents for a script portal are: (1) **scene/project files that execute code** (`.blend` auto-run, Maya scriptNodes; by analogy, AE `.aep`/`.ffx` carrying expressions, though AE expressions are far more limited than ExtendScript, which is unverified here); (2) **dependency tampering** (ComfyUI wheels, which maps to "shared helper libraries" pulled at install time); (3) **piracy bundles**; (4) **stolen or cloned uploads**. A portal hosting AE scripts that call `system.callSystem`, `File` and `Socket` (as the user's do) is hosting code with **full user privileges** once the permission toggle is on, so review matters.
- Practical policy set, drawn from the precedents: require **readable source for review** even when a `.jsxbin` is distributed (Greasy Fork and Comfy ban obfuscation; jsxbin's protection is weak anyway because of jsxer); run **static checks** for `callSystem`, `Socket`, `File.execute`, `eval` and network URLs; show a **permissions badge** ("writes files / network / runs shell") in the spirit of Obsidian's scorecard and Blender's manifest permissions; keep **hashes and signatures per release** and a **remote revoke** list for the portal's manager (as VS Code and Comfy do); **verify authors** for paid items. Do not rely on VirusTotal alone: the StealC `.blend` files scored zero detections.
- Hosting AI-written scripts raises the chance of unreviewed `callSystem`/network code and of near-duplicate clones (see §3), which strengthens the case for automated diffing and similarity checks.

### Gaps
- I found no documented case of malware distributed specifically as an **AE `.jsx`/`.jsxbin` script** or `.ffx` preset. That may mean none exist or that none have been reported; it is worth a targeted search later.
- Could not verify details of the Fab "detection tool" or Epic's statement.

## 3. Licensing: script licenses, license-key systems, copyright status of AI-generated code (US and Russia), and what this means for a portal hosting AI-written code

### Takeaway
Blender's official platform now requires **GPL-3.0-or-later** for all bpy add-ons. Raycast requires MIT. AE scripts have no license mandate and are often sold under proprietary EULAs with aescripts' closed licensing framework. Lemon Squeezy offers an off-the-shelf license-key API. In the US, purely AI-generated material is **not copyrightable** (Copyright Office Part 2 report, 29 Jan 2025). The D.C. Circuit affirmed this in *Thaler v. Perlmutter* (18 Mar 2025), and the Supreme Court **denied cert on 2 Mar 2026**. Human selection, arrangement and modification remain protectable. Russia's Civil Code (art. 1257) makes only a natural person an author. Courts treated AI (deepfake) as a *tool*, and protected the human-made work, in case A40-200471/2023 (2023–2024). A March 2026 Ministry of Digital Development (Минцифры) draft AI law reportedly adds rules for AI-created IP objects, but its text and status are unclear. For a portal this means: ask authors to **disclose AI assistance**, default to a permissive open license, and accept that heavily AI-generated scripts may carry thin or no copyright, which weakens takedown claims and makes paid exclusivity harder to defend.

### Cited Findings
**Licenses on existing platforms**
- A notice repeated on extensions.blender.org approval pages says **all add-ons using the bpy API must be released as GPL-3.0-or-later**, whatever the code's earlier license (GPL-2, MIT, ZLIB). Existing versions are grandfathered, but new updates must comply. The rationale is consistency with Blender's own license. The notice is undated, and the approval-queue pages are not formal policy documents. — [extensions.blender.org approval queue (e.g., Amaranth)](https://extensions.blender.org/approval-queue/amaranth); [approval queue: rhino-to-blender](https://extensions.blender.org/approval-queue/rhino-to-blender)
- Raycast requires `MIT` in each extension's `package.json`. — [Raycast: Prepare an extension for the Store](https://developers.raycast.com/basics/prepare-an-extension-for-store)
- aescripts supplies its **own end-to-end licensing framework** to authors who sell through it. Forum posts from 2016 and 2021 say developers receive it from aescripts staff. Customer flow: temporary serial, then permanent serial, then "Register" in the host app. Licenses from other stores (e.g., Motion Design School) are separate. — [Adobe Community: license key for my script](https://community.adobe.com/t5/after-effects-discussions/license-key-for-my-script/m-p/12461343); [aescripts forum comment](https://aescripts.com/forums/discussion/comment/9954/); [Motion Design School: Scripts license system](https://tools.motiondesign.school/support/licensing/scripts-license)
- **Lemon Squeezy License API:** a dedicated API to **activate / validate / deactivate** keys. Activation returns an `instance_id` the app stores. Keys can have activation limits, statuses are inactive/active/expired/disabled, and calls are rate-limited to 60 req/min. — [Lemon Squeezy docs: License API](https://docs.lemonsqueezy.com/api/license-api); [Validating license keys](https://docs.lemonsqueezy.com/guides/tutorials/license-keys)

**AI-generated code: United States**
- **Copyright Office, Part 2 report (29 Jan 2025):** copyright protects only human authorship. Outputs are protectable where a human determined sufficient expressive elements: a human work perceptible in the output, or creative selection, arrangement or modification. **Prompts alone are not enough.** AI assistance, or AI material inside a larger human work, does not bar protection. No new law is recommended, and decisions are case by case. — [U.S. Copyright Office NewsNet 1060](https://copyright.gov/newsnet/2025/1060.html); [Crowell & Moring summary](https://www.crowell.com/en/insights/client-alerts/us-copyright-office-releases-part-2-of-artificial-intelligence-report-clarifying-copyrightability-of-generative-ai-outputs)
- ***Thaler v. Perlmutter*:** the D.C. Circuit held on 18 Mar 2025 that the Copyright Act requires human authorship. The **Supreme Court denied certiorari on 2 Mar 2026**, so the human-only standard stands. — [Baker Donelson](https://www.bakerdonelson.com/supreme-court-denies-certiorari-in-thaler-v-perlmutter-ai-cannot-be-an-author-under-the-copyright-act); [Jones Day, Mar 2026](https://www.jonesday.com/de/insights/2026/03/jones-day-talks-women-in-ip--supreme-court-denies-review-of-thaler-v-perlmutter-ai-authorship-questions-remain)

**AI-generated works: Russia**
- Art. 1257 of the Civil Code (ГК РФ) recognizes as author only the **citizen (natural person)** whose creative labor created the work. It has no AI-specific rules. Russian scholars are split between "fully AI-made output is not protected" and case-by-case analysis that separates AI-as-tool from AI-as-creator. — [Garant blog: copyright for AI content (RU)](https://harant.ru/blog/urist-term/avtorskie-prava-na-kontent-sozdannyj-nejrosetyami-problemy-i-perspektivy/); [Tyumen State Univ. paper, 2023 (RU, PDF)](https://elib.utmn.ru/jspui/bitstream/ru-tsu/34877/1/Lapzgo_2023_237_243.pdf)
- **Deepfake case A40-200471/2023:** the Moscow Arbitration Court (АСГМ) in Dec 2023 awarded **500,000 RUB** to the rights holder (Рефейс технолоджис) of a deepfake Keanu Reeves video made by Адженда медиагрупп, against ООО «Бизнес-аналитика». The court called deepfake "an additional tool for processing video, not a way of creating it". The **9th Arbitration Appeal Court upheld it on 8 Apr 2024**. — [Pravo.ru: АСГМ protected deepfake video](https://pravo.ru/news/250272/); [Pravo.ru: appeal upheld](https://pravo.ru/news/252547/); [RAPSI, 11 Apr 2024](https://rapsinews.ru/digital_law/20240411/)
- **Минцифры draft law** «Об основах государственного регулирования сфер применения технологий искусственного интеллекта»: published 18 Mar 2026, with public comment until 15 Apr 2026. It reportedly includes a separate article 13 on protection of AI-created results and mandatory labeling of generated content, with a reported effective date of 1 Sep 2027. Conflicting report: Kommersant FM (an item marked as AI-assisted) says the Federation Council approved an AI-support law in July 2026, effective 1 Sep 2026. Neither the text of art. 13 nor the current status was verifiable. — [vc.ru: new AI regulation bill](https://vc.ru/legal/2847664); [vc.ru: Минцифры AI law, May 2026](https://vc.ru/ai/2936622-zakon-mintsifry-ob-ii); [Kommersant FM (conflicting)](https://www.kommersant.ru/doc/8863119)

**Platform policies on AI-made submissions**
- **GNOME Extensions** reviewers will not approve submissions with clear signs of AI generation. AI as a learning aid or for code completion is still allowed. — [It's FOSS: GNOME no-AI extensions](https://itsfoss.com/news/no-ai-extension-gnome/)
- **BlenderKit** does not accept "AI generators" in its library. — [BlenderKit: Guidelines for add-on creators](https://www.blenderkit.com/docs/guidelines-for-add-on-creators/)
- Blender's AI contribution policy reportedly covers core development, docs and bug reports but **not extensions** (secondhand forum summary). A forum anecdote describes an add-on whose code was run through an AI and re-uploaded by someone else while the original was still in review, and the copy was approved. — [BlenderArtists: developer meeting notes thread](https://blenderartists.org/t/developer-meeting-notes/1126008?page=146); [Blender devtalk: Extensions Platform thread](https://devtalk.blender.org/t/extensions-platform/34663?page=19)
- Superhive sells a product called "AI Shortcuts: Vibe Coding in Blender", so AI-assisted tooling is commercially present there. — [Superhive: AI Shortcuts](https://superhivemarket.com/products/ai-shortcuts)

### Inferences
- For a portal hosting "self-written and AI-assisted" scripts: (1) add an **AI-assistance disclosure field** (none / assisted / mostly generated), in line with the Copyright Office's human-contribution test and the RU draft law's labeling direction; (2) make a **permissive license the default** (MIT, matching the user's `package.json`), let authors choose GPL, and allow proprietary licenses only for paid items; (3) for Blender items, **enforce GPL-3.0-or-later** to stay compatible with the official platform and its rules; (4) expect that **clone and "AI-laundered" re-uploads** are hard to fight through copyright when the original is itself mostly AI-generated. That argues for provenance features (timestamps, first-publisher badges, similarity detection) rather than legal takedowns alone.
- The GPL/AI combination is an open risk: AI assistants may reproduce GPL code inside MIT-licensed AE scripts. The portal can at most warn about it and offer a similarity check.

### Gaps
- Could not search the US Copyright Office's March 2023 registration guidance (background knowledge, not verified: it requires disclosing more-than-de-minimis AI-generated content on registration), or the *Doe v. GitHub* (Copilot) appeal status.
- No primary source on Gumroad's license-key verify API (background knowledge: it exists). Paddle and Keygen not checked.
- Text of art. 13 of the RU draft law not available. The adoption status conflict is unresolved.
- No source found on aescripts' policy toward AI-generated scripts.
- A search summary said Superhive does not allow "fully AI-generated products with little or no human input", but no Superhive policy page was retrieved to confirm it.

## 4. Monetization: what works for small-tool communities, platform fees, and payout problems for authors in restricted countries (e.g., Russia)

### Takeaway
Take rates fall in tiers. Low: GitHub Sponsors 0% for individuals; Ko-fi 0% on donations (secondary source); Payhip 5% → 0% on paid plans; Lemon Squeezy 5% + 50¢; Adobe CC Marketplace 10%. Mid: Gumroad 10% + 50¢ direct; Patreon 10% for new creators since Aug 2025; Fab 12%; Tribute about 10%; Boosty about 11.7%. High: Superhive 30% on the free plan; Gumroad Discover 30%; Envato Elements authors get 50% of net. aescripts does not publish its split. Small-tool marketplaces are under pressure: Superhive's average earnings per creator fell from $523 to $375 between sales, and creators are moving to subscriptions. Russian authors largely lost Western payout rails in 2022 (Payoneer for Patreon ended 16 Dec 2022; itch.io payout providers stopped working). The domestic rails are Boosty and Tribute (Telegram). A portal serving RU and non-RU authors needs either an MoR with RU-compatible payouts or a "bring your own payment link" model.

### Inferences
- For a portal built around many cheap or free micro-scripts, the evidence favors **free-first plus tipping and pay-what-you-want** (the aescripts NYOP $0-minimum precedent; Nukepedia's scale on donations) over a high-commission store. Superhive's numbers show that even a healthy niche store spreads thin per creator.
- To keep fees low and legal exposure small, the portal could start as a **link-out model**: authors attach their own Gumroad, Lemon Squeezy, Payhip, Boosty, Tribute or GitHub Sponsors links, so the portal is not the seller of record. An in-house MoR store can come later. RU authors would attach Boosty or Tribute; non-RU authors would attach Western rails. A portal acting as seller of record for both groups would face sanctions/compliance issues.
- License keys for paid AE scripts could use Lemon Squeezy's License API from ExtendScript via `Socket` or `callSystem` + curl. That needs the file/network permission, which affects the user experience.

## 5. Community & discovery: which features successful snippet/script hubs use, and which correlate with traction

### Takeaway
I found little hard data linking specific features (forks, live previews, ratings) to traction. What the evidence does show: (a) **in-app install and updates** drive adoption (Obsidian passed 120M plugin downloads; Blender and Superhive moved to in-app repositories; Nukepedia's nuBridge; Reactor); (b) **trust signals** (scorecards, verification flags, open-source requirements, PR-based review) became standard in 2024–2026; (c) a **Git/PR-based submission flow** (Raycast) gives versioning, diffs and review for free. In 3D printing, newer hubs with rewards (MakerWorld, Printables) matched or overtook incumbent Thingiverse in traffic. That correlates with creator incentives, but causation is not shown.

### Cited Findings
- **Obsidian:** since the API launched in 2020, **more than 4,000 plugins and themes**, with **120M+ total plugin downloads**. In May 2026 it moved from GitHub-PR submission to "Obsidian Community", with automated scans and safety scorecards per plugin page. — [Obsidian blog: Future of plugins](https://obsidian.md/blog/future-of-plugins/); [GIGAZINE, May 2026](https://www.gigazine.net/gsc_news/en/20260513-obsidian-plugin-future)
- **Raycast:** submission is a PR to a public monorepo, reviewed first in, first out. PRs go stale after 14 days and close after 21 days of inactivity. Extensions must "bring value" not already offered by Raycast or other extensions, which is a duplicate-prevention rule. — [Raycast: Publish an extension](https://developers.raycast.com/basics/publish-an-extension); [Raycast Extensions Guidelines](https://manual.raycast.com/extensions-guidelines)
- **Greasy Fork:** readable-code rules (no minify/obfuscate) and moderator deletion are the main trust features (see §2). — [Greasy Fork code rules](https://greasyfork.org/he/help/code-rules)
- **Comfy Registry:** a **verification flag** in Manager for scanned nodes; planned author verification. — [Comfy Registry docs](https://docs.comfy.org/registry/overview.md); [Comfy Jan 2025 security update](https://blog.comfy.org/p/comfyui-2025-jan-security-update)
- **Superhive:** creator bundles, public coupons, and planned creator-run sales and advertising tools. In-Blender install and updates through a token-registered remote repository. — [Superhive: Inside the Hive](https://superhivemarket.com/posts/inside-the-hive-what-s-new-to-superhive-with-kyle); [Superhive remote extension support](https://superhivemarket.com/posts/blender-extension-support-launched-on-superhive)
- **Nukepedia:** volunteer-run, free, **2,000+ tools / 900,000+ users** (Apr 2025), in-app browser (nuBridge, "over 1,300 tools right inside of Nuke"), donation-funded. — [Digital Production](https://digitalproduction.com/2025/04/25/nukepedia-2-0-from-geekfest-to-gigabytes/); [Nukepedia nuBridge](https://www.nukepedia.com/nubridge/)
- **3D-model hubs (traffic proxy):** Semrush, Nov 2025: **MakerWorld about 31.7M** monthly visits, **Thingiverse about 21.4M**, **Printables about 20.4M** (estimates of visits, not users). An Oct 2024 analysis said Printables faced "a long road" to catch Thingiverse by model count. A 2025 roundup tells creators to look for rewards, tipping, paid downloads and contests. — [Fabbaloo: traffic analysis](https://www.fabbaloo.com/news/traffic-analysis-shows-makerworld-thingiverse-and-printables-leading-3d-model-sites); [Semrush: thingiverse.com competitors](https://ja.semrush.com/website/thingiverse.com/competitors); [Fabbaloo: Can Printables catch Thingiverse?](https://fabbaloo.com/?p=225899); [PixUp3D roundup 2025](https://pixup3d.com/blog/thingiverse-alternatives/)
- **Bounties/requests as a feature, with a failure precedent:** Bountysource changed owners (CanYa in 2017, "The Blockchain Group" in 2020), tried a 2020 ToS change to keep unclaimed bounties after two years (withdrawn after backlash), and by early 2023 had reportedly stopped paying developers and gone insolvent (forum reports). Projects such as elementary and Xfce left for GitHub Sponsors or refunds. — [elementary blog: Goodbye, Bountysource](https://blog.elementary.io/goodbye-bountysource-hello-github-sponsors/); [Mautic community debate](https://community.mautic.org/assemblies/product-team/f/39/debates/2); [Xfce/Shimmer blog, Jun 2020](https://simon.shimmerproject.org/2020/06/18/why-bountysource-why/); [boehs.org (allegation)](https://boehs.org/node/bountysource)

### Inferences
- Features with the best supporting evidence for an AE/VFX hub: **(1) a one-click install and update client** (every growing ecosystem above has one); **(2) visible trust signals** (permissions badge, review status, verified author); **(3) Git-backed versioning** (the user's GitHub repo could be imported directly as the source of truth, the Raycast/Reactor pattern); **(4) a compatibility matrix per host version**, which matters in AE given the 2025 ScriptUI breakages (§6); **(5) GIF/video previews**, which cost little for motion tools (no metric found, but standard on aescripts and Superhive product pages).
- **Requests and bounties** are worth adding only as a lightweight "request board" without escrow at first. Escrowed bounties carry custody risk, as the Bountysource collapse shows.

- No quantitative data found on Shadertoy, OpenProcessing, CodePen or Greasy Fork (counts, retention, or the effect of forks, likes or live previews). The search budget ran out before these could be checked.
- No data on whether ratings, comments or collections correlate with downloads on any creative-tool hub.
- No VS Code Marketplace size figures beyond the security statistics.

## 6. Unmet needs: what motion designers and VFX artists complain about or ask for

### Takeaway
The documented pain points are: (1) **version breakage**, e.g. AE 2025's new themes and ScriptUI rendering broke panels, and some users refused to upgrade because "I have too many time saver scripts that were affected"; (2) **abandonment**, as solo authors cannot keep up with AE updates and vendors discontinue tools; (3) **fragmented, inconsistent installation** (ScriptUI vs Scripts folders, ZXP installers, permission toggles); (4) **cost and piracy**: cracked AE and plugins are a major infostealer vector, which points to demand for cheap or free tools; (5) a **growing AI "vibe coding" wave** of non-programmers writing AE scripts, with no curated, safe place to share and vet them. I could not retrieve Reddit threads directly, and industry surveys (School of Motion 2017/2019) carry no tool-sourcing data.

### Cited Findings

### Inferences
- The user's collection (dozens of small single-purpose AE scripts such as "Set Opacity", "trimLayers" and "Round pathPoints") fits the gap the evidence points to: **many micro-utilities that are free or nearly free**, which do not justify a paid aescripts listing but need **compatibility tracking, easy install and safe vetting**.
- The features the evidence supports most are: (1) a **"works in AE 24/25/26" compatibility matrix** with user-submitted "works/broken" reports per version (directly answers the 2025 breakage complaints); (2) an **"adopt an abandoned script"** / fork flow for open-licensed tools whose authors stopped updating; (3) **one-click install that resolves shared libs and permissions**; (4) a **safe, reviewed home for AI-assisted scripts** with disclosure labels, because the vibe-coding wave produces many scripts with no vetting; (5) a **request board** ("I need a script that does X") that lets people with AI tools pick up requests. There is no direct metric for this demand, so this is an inference.
- A RU-language angle: RU authors cannot easily sell on Western stores (see §4), so a bilingual portal with Boosty/Tribute link-outs could serve an underserved supply side. This is an inference; no RU-specific survey was found.
